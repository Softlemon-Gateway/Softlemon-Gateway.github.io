# Softlemon API Documentation

Documentation site for the Softlemon Merchant and Partner APIs, built with
[Zudoku](https://zudoku.dev/) and served via GitHub Pages at
https://softlemon-gateway.github.io/.

## Structure

- `zudoku.config.jsx`: site configuration (theme, fonts, navigation, API sources).
- `specs/merchant/openapi.yaml`, `specs/partner/openapi.yaml`: the OpenAPI documents.
  All reference content lives here, including the intro prose, integration journeys
  and the 3DS test-cards table in `info.description`.
- `pages/guides/`: the guides, rendered under `/guides/`. Integration flow
  tutorials (accept a payment, authorize and capture, refunds, returning
  customers, partner integration) are authored in this repository. Reference
  guides (webhooks, transaction statuses, duplicate protection) originate in the
  api repository. The webhook admin API guide there is internal and deliberately
  not published.
- `public/`: static passthrough files copied to the site root as-is. Contains the
  favicon and redirect shims for legacy URLs (`merchant.html`, `partner.html`,
  `guides/webhooks.html`). `public/specs/` is generated by the prebuild step so the
  raw yaml URLs keep working. `public/collections/` holds the Postman collections
  generated from the specs, served at `/collections/`.
- `scripts/generate-snippets.mjs`: regenerates the 11-language request snippets in
  the flow guides (`npm run snippets`). Each request is defined once in
  `scripts/snippets/requests.mjs` and rendered through the same snippet engine the
  API reference sidecar uses, so guide and reference samples always match. Rerun
  after changing a request definition.
- `scripts/generate-postman.mjs`: regenerates the Postman collections from the
  specs (`npm run postman`). Rerun after any spec change.
- `diagrams/`: hand-maintained diagrams (not rendered on the site).
- `.github/workflows/deploy-pages.yml`: builds and deploys on push to main.
  **Inert until go-live** (see the checklist below).

## Local development

```sh
npm install
npm run dev        # dev server on http://localhost:3000
```

Production build and preview:

```sh
npm run build      # outputs static site to dist/
npm run preview    # serves the built site locally
```

## Content sources and the publish pipeline

The two OpenAPI specs are generated in the `api` repository by `make docs`
(Scribe for both audiences, then `scripts/clean_openapi_specs.php` for the
artifacts Scribe cannot suppress) and staged into its `docs/site/specs/`. On
pushes to `stage` that touch `docs/site/`, the api repository's
`publish-docs.yml` workflow copies only those two files into `specs/` here and
commits. It writes nothing else in this repository. Everything else on the
site (pages, guides, navigation, theme) is authored in this repository and
built by `deploy-pages.yml`.

Durable reference prose lives in the api repository sources: the spec intros
in `docs/openapi/descriptions/*.md`, endpoint and field prose in the
controller and FormRequest annotations, response examples in
`storage/responses/` and the outbound webhook contract in
`docs/openapi/webhooks.yaml`. Editing `specs/` here directly works until the
next publish overwrites it, so land spec changes upstream.

The guide pages under `pages/guides/` are authored here for a public audience
(no internal file paths, class names, log strings or incident details). The
api repository keeps its own internal copies under `docs/guides/`, which are
no longer published anywhere.

## Go-live checklist

1. Switch this repository's Settings > Pages > Source to "GitHub Actions".
2. Push to main. The deploy workflow builds and publishes the site.
3. Spot-check https://softlemon-gateway.github.io/: root redirect, both API docs,
   `/guides/webhooks`, legacy URLs (`/merchant.html`, `/partner.html`,
   `/guides/webhooks.html`) and the raw spec URLs under `/specs/`.
